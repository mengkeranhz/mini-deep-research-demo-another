# 原项目 mini-deep-research-demo 设计分析

本文基于只读阅读 `/Users/mengkeran/IdeaProjects/mini-deep-research-demo` 得出；原项目未做任何修改。

## 1. 总体判断

原项目是一套完全手写的 Java 21 Agent Harness，没有依赖 Spring AI、LangChain4j 或 LangGraph4j。它的核心价值不在“能调用工具”，而在以下工程约束：

- 把会膨胀的对话上下文与权威过程状态分离；
- 用外部账本保证数据跨轮、跨压缩、跨子 Agent 不丢；
- 用确定性闸门先拦截可计算的缺口，再使用 LLM 质量复核；
- 把技能、检索、任务、事实和对话全部落盘可审计。

## 2. Agent Loop

`Agent` 每轮执行：

1. 轮次上限检查；
2. 构造本次调用消息，并在尾部追加动态状态快照；
3. 调用 LLM，携带系统人格、工具定义、对话历史与 thinking/tool_use 协议块；
4. 无工具纯文本按状态分流；
5. 有工具则执行普通工具，`delegate_agent` 并发执行；
6. `final_answer` 进入终答闸门；
7. 超过 token 阈值时压缩上下文；
8. 周期性写运行账本。

关键取舍：

- **动态快照放尾部而非头部**：避免破坏稳定历史前缀，降低缓存失效；
- **快照不写入 state.messages**：天然避免旧快照堆积；
- **普通工具顺序执行**：共享 TaskStore/FactsStore 时避免并发写；
- **同批子 Agent 并发**：每个子 Agent 独立状态，合并时加锁。

## 3. 上下文管理

### 3.1 去噪

每轮注入的是瘦身快照：

- TaskStore：计划头、进度、可执行/阻塞、未完成任务；
- FactsStore：计数、覆盖缺口、最近新增/变更、维度索引；
- SubAgentStore：报告路径与冲突提示，不注入全文；
- 当前时间。

全量任务与事实只在压缩重建和终答校验时进入上下文。

### 3.2 压缩

触发依据是上次响应 inputTokens 超阈值。压缩时：

1. 用无工具 LLM 总结不含 tool_result 正文的执行稿；
2. 丢弃旧对话和 thinking；
3. 按优先级重建：原始述求、摘要、待修缺陷、技能全文、事实账本、搜索清单、子报告、旧草稿、继续指令；
4. 明确声明事实账本为最终权威，防止摘要或旧草稿锚定。

终答刚被拒的当轮不压缩，避免缺陷清单被摘要稀释。

### 3.3 内容审核恢复

网关返回 `Content Exists Risk` 时，原项目会丢弃累积历史，用原始述求与事实账本重建上下文；连续触发超过上限则失败退出，避免死循环。

## 4. 计划进度

`TaskStore` 包含：

- 当前任务：id、内容、依赖、状态、备注；
- 规划头：总体计划、硬约束、信息缺口；
- 首次规划基线：重规划只改变当前计划，不改变最终校验基准。

快照中 ready/blocked 是每次现算的派生状态，不持久化，避免任务状态更新后派生信息陈旧。

## 5. 事实账本

`FactsStore` 是最终权威。它管理：

- 覆盖目标：dimension → periods，作为终答覆盖检查表；
- 事实：维度、时期、口径、值、来源、状态、来源 Agent、critical；
- 状态：found / proxy / not_found；
- 最近变更：用于每轮瘦身快照；
- 子 Agent 事实合并与冲突。

重要规则：

- not_found 必须写明已尝试的检索方式，防止过早放弃；
- critical 且非 found 不能直接支撑主方案，必须给保守主方案和升级条件；
- 标签错位时提示照抄覆盖目标字符串重新入账，避免重复检索；
- 多来源同语义事实冲突时保留证据并要求终答前复核。

## 6. 搜索进度

`SearchLog` 记录行为而非结论：

- query、domains、命中数、来源 Agent；
- 查询归一化与 Jaccard 近似判断；
- web_search 回执提示语义相近的历史查询；
- 压缩重建时注入全量已检索清单，避免换措辞重复搜索。

## 7. 工具体系

工具由包扫描自动发现，再按父/子白名单注册：

- 规划：`analyze_query`、`update_task`；
- 技能：`load_skill`、`read_file`；
- 检索：`locate_sources`、`web_search`、`fetch_url`；
- 入账：`record_facts`；
- 计算/领域：`run_code`、高德地点/周边/路径、`render_card`；
- 终止：`final_answer`；
- 委派：`delegate_agent`（仅父 Agent）。

工具异常转为 error tool result 回传模型，而不是直接崩溃。`final_answer` 本身只提交答案，是否终止由 Agent Loop 的闸门结果决定。

## 8. Skill

技能目录标准布局：

```text
skills/<name>/SKILL.md
skills/<name>/schemas/*.json
skills/<name>/reference/*
skills/<name>/scripts/*
```

系统提示只注入 name/description；`load_skill` 后才加载全文。技能正文会进入：

- 规划器内部调用；
- 上下文压缩重建；
- 终答校验依据。

带 schemas 的技能要求领域事实使用 payload + schema 入账，避免只落成不可验证文本。

## 9. 子 Agent

`delegate_agent` 的关键设计：

- 子 Agent 独立任务、事实、搜索、技能状态与文件目录；
- 继承父事实切片和检索历史，但不递归委派；
- 同批最多 4 个并发；
- 报告全文落盘，父上下文只放路径与核对提示；
- 完成后事实与搜索按来源 Agent 合并，冲突保留；
- 多版本任务以一个版本一个完整交付物为第一拆分维度。

## 10. 终答闸门

顺序：

1. FactsStore 覆盖度、not_found 证据、多来源冲突；
2. critical 依赖降级检查；
3. 无工具 LLM 对照首次任务基线、事实账本、技能终检、子报告核对信息做质量复核。

只有五类 BLOCKER 可拒绝：事实错误、账本矛盾/遗漏、硬约束违反、关键缺口未声明、技能/关键依赖违反。补充性建议不阻塞。

## 11. 运行归档

每次运行独立目录，包含：

- 原始述求与系统提示；
- 任务、事实、搜索账本；
- 压缩前执行稿与完整对话；
- 最佳答案草稿；
- 技能与子 Agent 报告索引；
- 最终结果与运行摘要。

这使模型过程可回放、事实可追溯、失败可诊断。

## 12. 对 v2 的裁剪原则

v2 保留单 Agent 的核心研究闭环，暂缓并发子 Agent 与领域工具。这样能优先验证框架化后的核心不变量：上下文不膨胀、事实不丢失、终答可校验、过程可归档。
